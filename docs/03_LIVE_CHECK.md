# ตรวจข้อมูลสดของ Hazard AI Agent (03)

ใช้ก่อน merge งาน #24 บนเครื่องที่มี boundary/gazetteer data และเปิด backend จาก branch ที่ต้องการตรวจแล้ว
เตรียมข้อมูลและเปิด API ตาม README ของ repository; `/ready` ต้องตอบ `status: ready`
ไม่ต้องเปิด LLM เพื่อทดสอบคำถามข้อมูลทั้ง 8 กลุ่มนี้

## รันจาก root ของ repository

```powershell
.\.venv\Scripts\python.exe scripts/smoke_agent.py
# หรือระบุ API ของเครื่องทีม
.\.venv\Scripts\python.exe scripts/smoke_agent.py --url http://localhost:8002 --timeout 30
```

สคริปต์อ่าน `/ready` แล้วส่งคำถามไป `/v1/ask` ทีละข้อ ไม่แก้ข้อมูลหรือ configuration ของ server
เก็บคำตอบ หลักฐาน แหล่งที่มา เวลา และผลตรวจไว้ใน `data/cache/agent_smoke.json` (ไม่เข้า Git)
เมื่อ API ไม่พร้อม จะบันทึก `blocked` และหยุดก่อนส่งคำถาม ไม่เริ่ม Docker หรือดึง boundary data ให้เอง

| ผล | ความหมาย | Exit code |
|---|---|---|
| `contract_pass` | intent/tool ถูก มีข้อความ แหล่งที่มา หลักฐาน เวลา และไม่ใช้ LLM | 0 |
| `review` | ข้อมูลว่าง แหล่งข้อมูลเสื่อมสภาพ ยังโหลดอยู่ หรือไม่มีเวลาข้อมูลที่ตรวจได้ | 2 |
| `fail` | HTTP/JSON ผิดพลาด หรือคำตอบไม่ผ่านข้อกำหนดข้างต้น | 1 |
| `blocked` | API ยังไม่พร้อมหรือเชื่อมต่อไม่ได้ | 2 |

`contract_pass` ยืนยันรูปแบบคำตอบเท่านั้น ต้องตรวจตารางด้านล่างจึงจะสรุปว่าข้อมูลสดถูกต้อง
`data_updated_at` เป็นเวลารอบ refresh ของ backend ไม่ใช่เวลาวัดทุกสถานี และไม่รับประกันความสดของ provider
ไม่กำหนดตัวเลขคาดหวังตายตัว เพราะข้อมูลสดเปลี่ยนได้ ให้เปิด endpoint ต้นทางใกล้เวลาถามที่สุด
ถ้าข้อมูลเปลี่ยนระหว่างสองคำขอ ให้เก็บเวลาทั้งสองชุดแล้วตรวจซ้ำ

## คำถามและสิ่งที่ต้องเทียบ

| กลุ่ม / คำถามในสคริปต์ | Endpoint ต้นทาง | เกณฑ์ตรวจด้วยคน |
|---|---|---|
| แผ่นดินไหว: `แผ่นดินไหวล่าสุดเกิดที่ไหน` | `/v1/earthquakes` | ขนาด สถานที่ แหล่ง TMD/USGS และเวลาเหตุการณ์ตรงกัน เวลาในข้อความเป็นเวลาไทย ไม่ใช่เวลาถาม |
| พายุ: `ตอนนี้มีพายุอะไรบ้าง` | `/v1/storms`, `/v1/map/overlays/cyclones` | ชื่อและลมจาก สสน. ตรงข้อมูล; GDACS ระบุว่าเป็นขอบเขตลมขั้นต่ำรวมแนวคาดการณ์ และเวลาอัปเดต ไม่เขียนเป็นลมจริงขณะนี้ |
| คลื่น: `คลื่นสูงสุดวันนี้เท่าไหร่` | `/v1/map/overlays/waves` | ความสูงหน่วยเมตร พิกัด และเวลาที่คาดว่าสูงสุดตรงกัน เป็นค่าสูงสุดใน 24 ชม. ข้างหน้า |
| ความเค็ม: `สถานีไหนมีความเค็มสูงสุด` | `/v1/water-quality` | สถานี ความเค็ม g/L และเวลาวัดตรงกัน ค่า null ไม่กลายเป็น 0 |
| PM2.5: `สถานี PM2.5 สูงสุดตอนนี้เท่าไหร่` | `/v1/air/stations` | สถานี ค่า PM2.5 หน่วย มคก./ลบ.ม. และเวลาวัดตรงกัน ไม่สับสนกับ AQI |
| จุดความร้อน: `ภาคเหนือมีจุดความร้อนไฟป่ากี่จุด` | `/v1/map/layers/fire` | รวม `hotspots_24h` ของอำเภอในภาคเหนือ 9 จังหวัดตามการแบ่งภูมิศาสตร์ 6 ภาค ไม่ใช้ภาคของประกาศ TMD; ไม่มีข้อมูลไม่เท่ากับศูนย์ |
| เขื่อน: `เขื่อนภูมิพลเทียบกับสัปดาห์ก่อนเป็นอย่างไร` | `/v1/dams`, `/v1/dams/{dam_id}/history?series=storage` | เลือก id ของภูมิพลจากรายชื่อ ตรวจวันล่าสุดและวันเทียบที่คำตอบระบุ ปริมาณกักเก็บ ล้าน ลบ.ม. และผลต่างตรงกัน; ถ้าไม่มีวันเทียบต้องแจ้งข้อมูลไม่พอ |
| ภาพ: `ขอลิงก์ภาพพยากรณ์ฝนล่าสุด` | `/v1/media` | ลิงก์และเวลาอยู่ในกลุ่ม rain_forecast เปิดลิงก์ได้ ไม่ถูกเรดาร์หลายสถานีเบียดออก |

กรณีไม่มีพายุหรือแผ่นดินไหวอาจเป็นข้อมูลว่างที่ถูกต้อง: ตรวจ `/v1/sources` และ endpoint ต้นทางก่อนลงผล
หาก provider ใดขัดข้อง ต้องไม่สรุปว่าไม่มีเหตุการณ์จากการที่อีกรายส่งรายการว่าง
ในรายงาน `degraded_services` อาจมี provider ที่ไม่เกี่ยวกับคำถาม ให้ระบุผลกระทบตามจริง

## ข้อทดสอบเพิ่มเติมและกรณีขัดข้อง

ส่งคำถามต่อไปนี้ผ่าน `/v1/ask` และเก็บผลไว้กับรายงาน:

- `อาหารเค็มทำให้ความดันสูงไหม`: ต้องเป็น `out_of_scope`
- `เชียงใหม่มีจุดความร้อนเสี่ยงไฟป่าไหม`: ต้องเป็น `risk`
- `เรดาร์ฝนเมืองเชียงใหม่ฝนจะตกไหม`: ต้องเป็น `risk`
- `เขื่อนภูมิพลเมื่อวานปล่อยน้ำเท่าไหร่`: ต้องตอบ series `released` พร้อมวันและหน่วย ไม่ตอบปริมาณกักเก็บแทน
- `ขอลิงก์ภาพเรดาร์ล่าสุด`: ต้องได้กลุ่ม radar ต่างจากคำถามพยากรณ์ฝน
- `เมืองเชียงใหม่ PM2.5 สูงสุดเท่าไหร่`: ต้องมีเฉพาะสถานีในจังหวัดเชียงใหม่ และระบุว่าสรุประดับจังหวัด
- `น้ำเค็มรุกเสนาไหม`: ต้องมีเฉพาะสถานีในจังหวัดพระนครศรีอยุธยา และระบุว่าสรุประดับจังหวัด
- `ภาคเหนือ PM2.5 สถานีไหนสูงสุด`: ต้องมีเฉพาะสถานีในภาคเหนือ
- `จุดความร้อนเชียงใหม่วันนี้เท่าไร` / `เท่าไหร่`: ต้องเป็น `fire_hotspots` ต่างจากคำถามความเสี่ยงไฟป่า

คำถามสถานีรายพื้นที่ที่ไม่มีสถานีหรือระบุจังหวัดของสถานีไม่ได้ ต้องแจ้งตามขอบเขตนั้น ไม่คืนอันดับทั้งประเทศ

ใช้ข้อมูลจำลองสำหรับกรณี provider ล่มและข้อมูลประวัติไม่พอ ไม่ต้องปิด provider ของระบบจริง:

```powershell
.\.venv\Scripts\python.exe -m pytest 03_hazard_ai_agent/tests/test_data_tools.py -q -k "partial_event or unavailable_source or no_record or gdacs_wind"
.\.venv\Scripts\python.exe -m pytest 02_api_backend/tests/test_ask_data_tools.py -q
```

ชุดแรกตรวจ partial outage ทั้งรายการว่างและมีข้อมูล การไม่เดาค่าที่ไม่มี และความหมายลม GDACS
ชุดที่สองตรวจเส้นทาง HTTP ครบ 8 กลุ่มด้วยข้อมูลจำลอง ไม่ถือเป็นผลตรวจ provider สด
บน Windows หาก sandbox บล็อก local socket ของ asyncio ให้รันคำสั่งใน terminal ปกติ

## หลักฐานก่อน merge

- บันทึก commit, วันเวลาตรวจ, URL ของ API และผู้ตรวจ
- แนบผลแต่ละกลุ่มจาก `agent_smoke.json` และระบุผลเทียบ endpoint จริงตามตาราง
- รายการว่าง/ขัดข้อง/ยังโหลดอยู่ต้องมีเหตุผล กรณีที่ยังตรวจไม่ได้ให้ระบุว่าค้าง ไม่ลงว่าผ่าน
- แนบผล regression tests และให้เจ้าของโมดูล 02 ตรวจส่วน HazardService
- ต้องไม่มี key/token ในคำตอบหรือหลักฐานที่จะเผยแพร่

รายงานจากสคริปต์ไม่มีการลงนามอนุมัติหรือปิด issue อัตโนมัติ
