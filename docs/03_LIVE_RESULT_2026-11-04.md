## ผลจาก provider จริง

คำถามทั้ง 8 กลุ่มตอบ HTTP สำเร็จ ได้ intent และ tool ตามที่คาด พร้อม source และ `llm_used: false`
สคริปต์สรุป `review` เพราะ FIRMS ขัดข้อง และมี inputs ที่ยังโหลดอยู่
รอบสุดท้ายไม่มี `inputs_pending` ใน metadata รวมแล้ว แต่ overlay คลื่นยังเป็น `pending`
จึงยังไม่ถือว่าค่าคลื่นตรวจผ่าน

| กลุ่ม | ผลตรวจ |
|---|---|
| แผ่นดินไหว | หลักฐาน 5 รายการตรงกับ `/v1/earthquakes`; ข้อความมีขนาด สถานที่ และเวลาไทย |
| พายุ | ThaiWater และ GDACS สถานะ `ok: true` แต่มี 0 รายการทั้งคู่ คำตอบแจ้งไม่พบรายการ; ยังไม่มีเหตุการณ์จริงให้ตรวจค่าลม GDACS |
| คลื่น | overlay เป็น `pending` และไม่มี feature คำตอบแจ้งยังไม่มีข้อมูล; ยังไม่ยืนยันค่าคลื่นสด |
| ความเค็ม | หลักฐาน 5 สถานีตรงกับ `/v1/water-quality`; ข้อความแสดงค่า หน่วย และเวลา |
| PM2.5 | หลักฐาน 5 สถานีตรงกับ `/v1/air/stations`; ข้อความใช้ค่า PM2.5 และหน่วย มคก./ลบ.ม. |
| จุดความร้อน | FIRMS ตอบ HTTP 400, source status เป็น `ok: false`; agent แจ้งว่ายังนับไม่ได้ ไม่ตอบเป็น 0; ยังไม่ยืนยันผลรวมสด |
| ประวัติเขื่อน | series ในหลักฐานตรงกับ endpoint history; ภูมิพล 4 พ.ย. 9,599 เทียบ 28 ต.ค. 9,578 เพิ่ม 21 ล้าน ลบ.ม. ตามการปัดเศษในข้อความ |
| ภาพพยากรณ์ | ลิงก์ในหลักฐานทั้ง 5 อยู่ใน rain_forecast; ลิงก์แรกเปิดได้ HTTP 200, `image/jpeg` |

ตรวจคำถาม regression เพิ่มกับ API จริงอีก 5 ข้อ:

- คำถามอาหารเค็ม → `out_of_scope`
- จุดความร้อนกับความเสี่ยงไฟป่าเชียงใหม่ → `risk`
- เรดาร์กับคำถามฝนจะตกไหมที่เมืองเชียงใหม่ → `risk`
- น้ำระบายจากภูมิพลเมื่อวาน → `dam_history`, เรียก `get_dam_history(1, released)`
- ขอภาพเรดาร์ → `media`, เรียก `get_media()`

รายงานดิบอยู่ใน cache ของเครื่องผู้ตรวจ ไม่เข้า Git:
