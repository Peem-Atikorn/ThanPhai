# ปรับหน้าเว็บทันภัยและแก้ข้อรีวิวด้านการอ่านข้อมูล

ย้ายตัวเลือกภัย 6 หมวดและการค้นหาพื้นที่มาไว้เหนือแผนที่ พร้อมพื้นหลังเฉพาะหมวด
ข้อความบนหน้าหลักคือ “รู้ภัยก่อน ปลอดภัยกว่า” และระบุชัดว่าภาพพื้นหลังเป็นภาพประกอบ ไม่ใช่เหตุการณ์ปัจจุบัน

## การแก้ตามรีวิว

- ย้ายสีประจำภัยไปใช้ที่หัวแผนที่และขอบการ์ด เนื้อหาแผนที่ พื้นที่ สถานี และผู้ช่วยใช้พื้นขาวทึบ
  จึงอ่านเวลา แหล่งข้อมูล สถานะโหลด และปุ่มแท็บได้ โดยไม่ต้องไล่ override ตัวอักษรเป็นขาวราย selector
- ปุ่ม “แม่น้ำ” ด้านบนส่งคำขอล้างขอบเขตจังหวัดทุกครั้ง รวมถึงกดซ้ำขณะอยู่ในหมวดเดิม
  ส่วนปุ่ม “สถานีวัดน้ำในจังหวัดนี้” ยังเปิดรายการเฉพาะจังหวัดได้
- ลบ props `initialQuery` / `initialHazard` / `initialView` และ effect ค้นหาอัตโนมัติที่ไม่ได้ใช้งาน
- ลบ CSS 17 class ที่เลิกใช้ รวมกฎซ้ำ และให้ปุ่มค้นหามี base display เพียงตำแหน่งเดียว
- ปุ่มค้นหาในแผงเริ่มต้นเปิด dialog เดียวกับปุ่มด้านบน คู่มืออธิบาย flow ปัจจุบัน
- ใช้ข้อความที่มองเห็นเป็น accessible name ของปุ่มค้นหา ไม่มี aria-label ที่ขัดกับข้อความ
- ย่อภาพ WebP รวมจาก 1,344,978 เป็น 742,342 bytes และเพิ่มบันทึกที่มา/สถานะสิทธิ์

## การตรวจสอบที่ทำแล้วในชุดทำงาน

รันทดสอบ state/event handlers ซ้ำได้หลังติดตั้ง dependencies: `node scripts/check-landing.cjs`

- ทดสอบ event handler และ state transition ของ component จริงด้วย hooks/API fixtures:
  เปิดค้นหาจาก empty state, เลือกจังหวัด, เปิดสถานีเฉพาะจังหวัด, สลับหมวดแล้วกลับแม่น้ำ, และกดแม่น้ำซ้ำ
- React server render ตรวจ 3 มุมมอง, ไม่มี toolbar/search ซ้ำ, หัวเรื่องเดียว และลิงก์ฉุกเฉิน
- ตรวจ syntax ของ TS/TSX 11 ไฟล์ และ parse CSS ทั้งสองไฟล์
- คำนวณ contrast จากคู่สีที่ประกาศ: เนื้อหารองบนพื้นขาว 5.51:1, ลิงก์ 11.62:1,
  แท็บไม่ active 4.99:1, ตัวโหลดแผนที่ 12.24:1, ตัวอักษรขาวบนหัวแผงทั้ง 6 สีต่ำสุด 4.90:1
  นี่เป็นการตรวจคู่สี ไม่ใช่ browser-wide WCAG audit
- ยังไม่ได้รัน Next.js production build หรือทดสอบ backend/map integration แบบครบระบบ

## ที่มาและสิทธิ์ของภาพ

ดู [บันทึกภาพ](../public/images/README.md): ชายฝั่งและไฟป่าสร้างด้วย OpenAI ในแชทนี้;
ภาพน้ำท่วมและฝน/พายุเป็นไฟล์ที่ผู้ใช้ส่งมาและอนุญาตให้นำลงเว็บ แต่แหล่งผลิต/ใบอนุญาตต้นทางยังรอยืนยัน

## ภาพหน้าจอแต่ละหมวด

ยังไม่มีภาพหน้าจอใหม่แนบในชุดนี้: browser launch ในสภาพแวดล้อมจัดทำไม่สำเร็จ
หลังติดตั้งชุดแก้และรันเว็บจริงแล้ว ใช้ Node.js 22+ กับ Chrome/Edge:

```powershell
node scripts/capture-pr-screenshots.cjs http://localhost:3000
```

สคริปต์เปิดเว็บจริง ไม่ mock API/แผนที่ จับ 6 หมวดที่ viewport 1440 × 1100 และภาพมือถือหนึ่งภาพ
พร้อมเช็กการเปิด dialog จากแผงเริ่มต้น, accessible name, พื้นการ์ดขาว และ horizontal overflow ที่ 1440/1024/768/390/320 px
บันทึกที่ `docs/pr-screenshots/` พร้อม README ซึ่งใช้แนบภาพใน PR ได้
อย่าทำเครื่องหมายว่าจับภาพสำเร็จจนกว่าสคริปต์จะจบด้วย PASS และตรวจภาพจริง
